# متجر التنوع الراقي — دليل تجميع ونشر الباك إند

هذا الدليل لك تحديداً بما أنك تجمعين الملفات من الجوال. اتبعي الخطوات بالترتيب.

## 1. هيكل الملفات (رتّبيها هكذا بالضبط)

```
altanawwu-store/
├── server.js
├── package.json
├── schema.prisma          → انقليه إلى: prisma/schema.prisma
├── middleware/
│   └── security.js
├── routes/
│   ├── products.js
│   ├── orders.js
│   ├── fx.js
│   └── staffAuth.js
├── utils/
│   └── upload.js
├── .env                    → أنشئيه بنفسك (راجعي القسم 3)
└── frontend/               → ملفات Netlify الثابتة (index.html/style.css/script.js) منفصلة، تُرفع في مكان آخر
```

⚠️ **مهم:** ملف `schema.prisma` يجب أن يوضع داخل مجلد اسمه `prisma/` وليس في الجذر (شرط من Prisma نفسه).

## 2. الحسابات المجانية التي تحتاجين إنشاءها قبل التشغيل

| الخدمة | الغرض | الرابط |
|---|---|---|
| قاعدة بيانات PostgreSQL | تخزين البيانات | Railway / Supabase / Neon (خطة مجانية تكفي للبداية) |
| Cloudinary | تخزين صور المنتجات وسندات التحويل | cloudinary.com |
| بريد SMTP | إرسال إشعارات الطلبات | Gmail (بكلمة مرور تطبيقات) أو Resend.com |
| استضافة الباك إند | تشغيل السيرفر فعلياً | Render.com (الأسهل للبدء من الجوال) |

## 3. ملف `.env` (أنشئيه في جذر المشروع، ولا ترفعيه أبداً لأي مكان عام)

```

SMTP_USER="your@gmail.com"
SMTP_PASS="..."

FRONTEND_ORIGIN="https://اسم-موقعك.netlify.app"
YER_PER_SAR_FACTOR=106
PORT=4000
```

## 4. خطوات النشر الفعلي على Render.com (من الجوال بالكامل)

1. ارفعي مجلد المشروع كاملاً إلى مستودع GitHub جديد (يوجد تطبيق GitHub للجوال، أو ارفعي الملفات مباشرة من واجهة github.com عبر متصفح الجوال — "Add file → Upload files").
2. سجّلي في Render.com بحساب GitHub.
3. New → Web Service → اختاري المستودع.
4. Build Command: `npm install && npx prisma generate`
5. Start Command: `npm start`
6. أضيفي كل متغيرات `.env` أعلاه من تبويب Environment في Render (لا ترفعي ملف .env نفسه أبداً).
7. بعد أول نشر ناجح، افتحي Shell الخاص بالخدمة من لوحة Render ونفّذي مرة واحدة:
   ```
   npx prisma migrate deploy
   ```
   هذا ينشئ كل الجداول فعلياً في قاعدة البيانات.
8. أنشئي حساب المالك مرة واحدة فقط عبر إرسال طلب POST إلى:
   `https://اسم-خدمتك.onrender.com/api/staff/setup-owner`
   بالحقول: `name`, `email`, `password` — يمكنك تنفيذه من تطبيق مثل "HTTP Shortcuts" على أندرويد أو "Shortcuts" على آيفون بدون أي كمبيوتر.
9. بعدها هذا المسار يُغلق تلقائياً ولا يمكن إنشاء مالك ثانٍ منه (حماية مقصودة).

## 5. حالة كل ملف حتى الآن

- ✅ `schema.prisma` — قاعدة البيانات الكاملة + جداول الموظفين وسجل المراقبة (RBAC حقيقي)
- ✅ `middleware/security.js` — Helmet، حد لعدد الطلبات، تنظيف المدخلات (XSS)، حماية Origin (CSRF)، تحقق JWT وصلاحيات
- ✅ `server.js` — OTP للعملاء، بحث، تركيب كل المسارات، طبقة حماية مفعّلة بالكامل
- ✅ `routes/products.js` — CRUD كامل، الآن **محمي**: الإضافة/التعديل/الحذف تتطلب تسجيل دخول موظف بصلاحية `products:write`
- ✅ `routes/orders.js` — إنشاء الطلب (بريد فوري + كوبون تلقائي) + قائمة/تفاصيل/تحديث حالة محمية للوحة التحكم
- ✅ `routes/staffAuth.js` — تسجيل دخول المالك/الموظفين، إنشاء موظفين بصلاحيات محددة، سجل مراقبة (Audit Log)
- ✅ `routes/fx.js` — سعر صرف SAR حقيقي محدَّث كل 6 ساعات (وليس رقماً ثابتاً للأبد كما كان في نسخة Netlify)
- ✅ `utils/upload.js` — رفع الصور السحابي (Cloudinary)
- ✅ ملفات Netlify الثابتة (`index.html`/`style.css`/`script.js`) — واجهة كاملة تعمل بـ LocalStorage، لم تُربط بعد بهذا الباك إند

⏳ **المتبقي فعلياً، وبصراحة عن كل بند:**

| البند | الحالة |
|---|---|
| ربط واجهة Netlify بهذا الباك إند الحقيقي | لم يبدأ — حالياً كل نسخة تعمل بمعزل عن الأخرى |
| العلامة المائية التلقائية على الصور | تحتاج Cloudinary Transformation إضافية في `utils/upload.js` |
| تسجيل دخول Google/Apple للعملاء | يحتاج مفاتيح OAuth حقيقية منك من Google Cloud Console / Apple Developer |
| صفحة VIP الكاملة للعميل (طلبات، عناوين، نقاط) | تحتاج تصميم واجهة + مسارات API جديدة |
| غرفة عرض 3D 360° | مشروع منفصل بحد ذاته (Three.js + نماذج 3D لكل منتج) |
| فحص AI للصور المرفوعة من العملاء | يحتاج خدمة ذكاء اصطناعي خارجية (مثل Google Vision) |

## 6. توصيات إضافية أنصح بها بصدق (لم أطبّقها كلها الآن لتفادي إثقالك، لكنها تستحق التخطيط لها)

1. **قبل الإطلاق الفعلي**: بدّلي `FRONTEND_ORIGIN` من `*` إلى رابط متجرك الحقيقي فقط — هذا يقفل الـ API عن أي موقع آخر غير متجرك.
2. **نسخ احتياطي لقاعدة البيانات**: فعّلي النسخ الاحتياطي التلقائي من إعدادات Railway/Supabase (عادة زر واحد) — لا تعتمدي على الذاكرة فقط.
3. **رقابة الأخطاء**: أنشئي حساباً مجانياً في Sentry.io وأضيفيه لاحقاً لمراقبة أي عطل في السيرفر فور حدوثه بدل انتظار شكوى عميلة.
4. **صفحة سياسة الخصوصية والاستبدال والاسترجاع**: مطلوبة قانونياً وتجارياً لأي متجر إلكتروني جاد، ولم تُذكر في أي طلب سابق.
5. **اختبار بعدد قليل من المنتجات الحقيقية أولاً** (10-15 منتجاً بصور حقيقية) قبل تعميم الكتالوج الكامل، لرصد أي مشكلة قبل انتشارها.
